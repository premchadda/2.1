Request Flow Architecture
How admin requests are processed
1
Client Request Initiation
Admin user action triggers API call from React frontend. JWT token from localStorage is attached to Authorization header as Bearer token.
axios.get('/api/admin/users', { headers: { Authorization: `Bearer ${token}` } })
2
JWT Token Verification
The protect middleware extracts and verifies the JWT using JWT_SECRET. Decoded user info is attached to req.user.
const decoded = jwt.verify(token, process.env.JWT_SECRET)
3
Admin Role Verification
The admin middleware checks if req.user.role === 'admin'. Returns 403 if not authorized.
if (req.user && req.user.isAdmin) { next() } else { res.status(403) }
4
Database Operation
Controller executes dbHelpers methods with whitelisted table names. All queries use parameterized statements to prevent SQL injection.
const items = await dbHelpers.find('users', { isActive: true })
5
Response Generation
Data is transformed (snake_case → camelCase), sensitive fields removed, and JSON response returned with success status.
res.json({ success: true, data: sanitizedUsers })

Common architecture used across all manager components
Standard Manager Component Pattern 
// Every manager component follows this lifecycle pattern:
import { useState, useEffect } from 'react'
import api from '../../shared/lib/api'
export default function ResourceManager() {
// State Management
const [items, setItems] = useState([])
const [loading, setLoading] = useState(true)
const [error, setError] = useState(null)
const [isEditing, setIsEditing] = useState(false)
const [currentRecord, setCurrentRecord] = useState(null)
// Data Fetching on Mount
useEffect(() => {
fetchItems()
}, [])
const fetchItems = async () => {
try {
const response = await api.get('/api/admin/resource')
setItems(response.data.data || [])
} catch (err) {
setError(err.message)
} finally {
setLoading(false)
}
}
// CRUD Operations
const handleSave = async (formData) => {
if (currentRecord) {
await api.put(`/api/admin/resource/${currentRecord._id}`, formData)
} else {
await api.post('/api/admin/resource', formData)
}
setIsEditing(false)
fetchItems()
}
const handleDelete = async (id) => {
await api.delete(`/api/admin/resource/${id}`)
fetchItems()
}
// Render: Table + Modal Pattern
return (
<div>
{loading ? <LoadingSpinner /> : <DataTable data={items} />}
{isEditing && <FormModal onSubmit={handleSave} />}
</div>
)
}

Authentication & Authorization
Security middleware chain
middleware/auth.middleware.js 
// =========================================
// JWT PROTECTION MIDDLEWARE
// =========================================
export const protect = async (req, res, next) => {
try {
let token
// 1. Extract token from Authorization header or cookies
if (req.headers.authorization?.startsWith('Bearer')) {
token = req.headers.authorization.split(' ')[1]
}
if (!token && req.cookies?.token) {
token = req.cookies.token
}
if (!token) {
return res.status(401).json({
success: false,
message: 'Not authorized, no token provided'
})
}
// 2. Verify JWT token
const decoded = jwt.verify(token, process.env.JWT_SECRET)
// 3. Fetch user and validate
const user = await dbHelpers.findById('users', decoded.id)
if (!user) {
return res.status(401).json({
success: false,
message: 'Not authorized, user not found'
})
}
// 4. Check account status
if (user.isActive === false) {
return res.status(403).json({
success: false,
message: 'Account is deactivated. Please contact support.'
})
}
if (user.emailVerified === false) {
return res.status(403).json({
success: false,
message: 'Please verify your email to continue.'
})
}
// 5. Attach user to request
const { password, ...userWithoutPassword } = user
req.user = { ...userWithoutPassword, isAdmin: user.role === 'admin' }
next()
} catch (error) {
return res.status(401).json({
success: false,
message: 'Not authorized, token failed'
})
}
}
// Alias for protect
export const auth = protect
// Optional auth - attaches user if token exists
export const optionalAuth = async (req, res, next) => {
try {
let token
if (req.headers.authorization?.startsWith('Bearer')) {
token = req.headers.authorization.split(' ')[1]
if (process.env.JWT_SECRET) {
const decoded = jwt.verify(token, process.env.JWT_SECRET)
const user = await dbHelpers.findById('users', decoded.id)
if (user && user.isActive !== false && user.emailVerified !== false) {
const { password, ...userWithoutPassword } = user
req.user = { ...userWithoutPassword, isAdmin: user.role === 'admin' }
}
}
}
next()
} catch (error) {
next()
}
}
// =========================================
// ADMIN ROLE MIDDLEWARE
// =========================================
export const admin = (req, res, next) => {
if (req.user && req.user.isAdmin) {
next()
} else {
res.status(403).json({
success: false,
message: 'Not authorized as admin'
})
}
}
// =========================================
// PRO PASS MIDDLEWARE
// =========================================
export const proPass = (req, res, next) => {
if (req.user && req.user.isProUser) {
next()
} else {
res.status(403).json({
success: false,
message: 'Pro Pass required for this resource'
})
}
}

Security Features
Implemented security measures
🔒
JWT Token Auth
Bearer token authentication with configurable expiration. Tokens stored in localStorage and/or httpOnly cookies.
✅
Role-Based Access
Three-tier middleware chain: protect → admin → proPass. Each route can require specific authorization levels.
🚫
SQL Injection Prevention
Whitelisted table names in dbHelpers. All queries use parameterized statements with $1, $2 placeholders.
📝
Input Validation
Schema-based validation middleware for POST/PUT requests. Validates types, lengths, and required fields.
🔄
Connection Pooling
PostgreSQL connection pool with max 20 connections, automatic reconnection, and transient error retry logic.
🗑️
Soft Delete System
All deletions set is_active=false. RecycleBin allows restore. Permanent delete requires explicit action.

Current Limitations & Issues
Known problems and areas needing improvement
🔴 Critical
No Pagination on Most Endpoints
Most GET endpoints return all records without pagination. For large datasets (questions, users), this causes performance issues and potential memory exhaustion.
🔴 Critical
Missing Audit Logging
No comprehensive audit trail for admin actions. Cannot track who made what changes and when. Critical for compliance and debugging.
🟡 Medium
No Rate Limiting
Admin endpoints lack rate limiting, making them vulnerable to abuse or accidental DoS from buggy admin tools.
🟡 Medium
Limited Bulk Operations
Only questions and notifications support bulk operations. Other resources require individual API calls for batch updates.
🟡 Medium
No Search/Filter on Many Endpoints
Many endpoints lack server-side search and filtering. UsersManager implements client-side filtering which doesn't scale.
🟡 Medium
Inconsistent Error Handling
Some endpoints return detailed error messages while others return generic errors. Inconsistent HTTP status code usage.
🟢 Low
No Caching Layer
Frequently accessed data (categories, settings) is fetched from database on every request. Could benefit from Redis caching.
🟢 Low
Limited Export Functionality
UsersManager has export button but no implementation. No CSV/Excel export for other resources.
