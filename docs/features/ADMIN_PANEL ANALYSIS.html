⚙️ Key Technical Implementations

Custom Order vs. Dynamic Feeds

🔄
Display Order Logic

Admins have "Drag and Drop" or numeric input to set the display_order of static libraries (syllabus chapters, test series catalog). This strict ordering is intentionally ignored in dynamic student UI sections.

Dynamic sections: "Continue Learning," "Recently Added," "Recommended for You" — sorted by last_accessed_at or created_at timestamps.

Soft Deletion Logic

🗑️
Safe Deletion Pattern

When an admin clicks "Delete" on a test or PDF, the system does not drop the row from Supabase. Instead, it updates a boolean column: is_deleted = true.

-- Deletion SQL Pattern
UPDATE tests SET is_deleted = true WHERE id = ?;

-- Frontend Query Pattern  
SELECT * FROM tests WHERE is_deleted != true;

-- Admin Recycle Bin Query
SELECT * FROM tests WHERE is_deleted = true;

Middleware Stack

1

protect Middleware

Verifies JWT token from Authorization header. Extracts user info and attaches to req.user.

2

admin Middleware

Checks if req.user.role === 'admin'. Returns 403 if not authorized.

3

validateBody Middleware (Optional)

Validates request body against predefined schemas. Sanitizes and transforms input.

4

Route Handler

Executes business logic using dbHelpers for database operations.

admin middleware ensures only users with role='admin' can access

Self-Deletion Prevention

Input Validation

// Validation schemas using custom validator const testSeriesSchema = createSchema() .field('name', { type: 'string', required: true, minLength: 2, maxLength: 200 }) .field('description', { type: 'string', required: false, maxLength: 2000 }); // Applied to route router.post('/test-series', validateBody(testSeriesSchema), handler);

⚠️ SQL Injection Prevention

Table names are whitelisted in postgres-helpers.js. The getTableName() method only accepts predefined collection names, preventing SQL injection through dynamic table names.

// Whitelisted table map this.tableMap = { users: 'users', testSeries: 'test_series', tests: 'tests', // ... only these are valid }; getTableName(collection) { const tableName = this.tableMap[collection]; if (!tableName) { throw new Error(`Invalid collection name: ${collection}`); } return tableName; }

Error Handling

All errors are caught and returned with appropriate HTTP status codes:

Status Code Scenario
200 Success
201 Resource created
400 Validation error / Bad request
401 Unauthorized (invalid/missing token)
403 Forbidden (not admin)
404 Resource not found
500 Server error

📌 Best Practices

  • Always use soft delete (is_active = false) instead of hard delete
  • Add validation schemas for all POST/PUT endpoints
  • Log admin actions to activity_logs table
  • Use transactions for operations affecting multiple tables
  • Return meaningful error messages without exposing internals
  • Calculate counts dynamically rather than storing redundant data
