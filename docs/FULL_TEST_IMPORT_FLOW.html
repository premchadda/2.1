Creates FormData, appends file, calls adminAPI.uploadFullTestJson(fd) with 5-minute timeout.

STEP 1B Backend receives file via Multer (150MB max)

FullTestImportModal.jsx :253-300
buildHierarchy() nests tests: Root → ExamCategory → Exam → Series → Stage → Subcategory → Test. User can select/deselect individual tests or entire branches. Search filtering by title, year, category.
STEP 3 User optionally previews a single test

Phase 2 — API Route Handling
Express routes with auth + file upload middleware
UPLOAD POST /api/import/full-test/upload
apps/backend/src/modules/import/bulkImport.routes.js :280-335
Middleware: protect → admin → fullTestUpload.single('file') (multer memory storage, 150MB). Parses JSON, saves temp file, validates schema, returns test list.
PREVIEW GET /api/import/full-test/preview-test/:index
apps/backend/src/modules/import/bulkImport.routes.js :341-370
Reads temp file from disk, parses JSON, extracts test at given array index, returns full test object with all sections and questions.
IMPORT POST /api/import/full-test/import-selected
apps/backend/src/modules/import/bulkImport.routes.js :376-463
Receives { indices: [0, 2, 5], strict: true }. Reads temp file, iterates over selected indices, calls importFullTest(test, config) for each. Accumulates results per test into imported[] and failed[].
POST /api/import/full-test/import-selected
Note: Frontend sends sequential requests (one per test) in a for-loop with progress tracking. No BullMQ queue — fully synchronous.
ALT POST /api/import/full-test/import (direct single-test)
apps/backend/src/modules/import/bulkImport.routes.js :208-272
Simpler path: upload JSON file directly, calls importFullTest(json, config) immediately. On success, moves file to organized folder path: uploads/test-imports/imported/{examCategoryId}/{examId}/{stageId}/...
ALT POST /api/import/full-test/preview (dry-run)
apps/backend/src/modules/import/bulkImport.routes.js :159-206
Calls importFullTest(json, { dryRun: true }). Returns summary without writing to database. Uses ROLLBACK at end instead of COMMIT.
3
Phase 3 — Core Import Engine
fullTestImporter.js — 900 lines, single transaction
3.1 BEGIN Transaction + Clear Caches
apps/backend/src/services/import/fullTestImporter.js :373-377
await client.query("BEGIN") — acquires DB client from pool. Clears slugCache (Map) and columnCache (Map).
3.2 Resolve 9 Slug Foreign Keys
fullTestImporter.js :380-425
Converts hierarchical slug strings to integer IDs using resolver functions. Each resolver uses either findSlug() (strict mode — find only) or upsertSlug() (lenient — find or create).
exam_categories exams stages test_categories test_series subjects chapters topics subtopics
Aliases handled: "tier-1" → "tier-1-pre", "prelims" → "tier-1-pre", "pyqs" → "pyps", 4-digit years get parent "year-based".
3.3 Pre-commit Validation
fullTestImporter.js :226-244
validateBeforeCommit(json, result) — warns if totalQuestions doesn't match actual questions in sections, warns if section questionCount doesn't match actual questions array length.
3.4 Insert Test Record (50+ columns)
fullTestImporter.js :431-542
Builds massive testRow object with basic fields, categorization, 10+ JSONB config blocks (show_config, timing_config, proctoring, adaptive, features...), flags, legacy fields, and import tracking. SQL is dynamically built to skip columns that don't exist in actual DB via information_schema.columns.
tests → INSERT
Slug uniqueness: ensureUniqueSlug() appends timestamp if duplicate found.
3.5 Process Sections (per section)
fullTestImporter.js :548-600
For each section: resolve subjectId, build sectionRow (20+ fields including duration, time_limit, display_order with SECTION_ORDER_MAP for SSC CGL standard ordering, question_count, total_marks, negative_marking, flags, instructions JSONB, section_code).
test_sections → INSERT
3.6 Process Questions (per question, with SAVEPOINT)
fullTestImporter.js :601-736
For each question: SAVEPOINT q{N} → resolve FKs → extract bilingual text (English + Hindi from multiple field formats) → convert correct answer from 1-indexed to 0-indexed → skip if no text or text < 3 chars → dedup check via external_question_id + test_id → INSERT into questions → INSERT into test_questions junction → on error: ROLLBACK TO SAVEPOINT, record error, skip question.
questions → INSERT test_questions → INSERT
Error handling: Each question is independently rollback-safe. Failed questions are logged and skipped — processing continues.
3.7 Update Test Totals
fullTestImporter.js :749-758
UPDATE tests SET total_questions = $1, total_marks = $2, updated_at = NOW() WHERE id = $3
3.8 Log Import + COMMIT
fullTestImporter.js :760-793
Inserts audit record into import_logs (imported_by, source, file_name, imported count, failed count, errors JSONB, metadata JSONB). Then COMMIT — or ROLLBACK if dryRun. Client released in finally block.
import_logs → INSERT
